# Customer feedback log

A structural template for tracking real feedback once Aegis has real
customers. Deliberately empty — no rows exist yet, and none should be
invented. Add a row per distinct piece of feedback as it comes in from
the first customer conversations (see Phase 7's closing principle: real
customer validation before more feature work).

| Customer | Problem | Severity | Frequency | Requested feature | Current workaround | Business impact | Decision |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

**Column guide:**

- **Customer** — company name or anonymized identifier.
- **Problem** — what they were trying to do and where it broke down.
- **Severity** — blocker / high / medium / low.
- **Frequency** — how often this comes up (one-off vs. every session).
- **Requested feature** — what they asked for, in their words.
- **Current workaround** — what they're doing instead today, if anything.
- **Business impact** — what it's costing them, or what adopting Aegis
  is worth to them, if they said so.
- **Decision** — build now / backlog / won't build, and why.
